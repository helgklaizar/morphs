# Глоссарий предметной области (Glossary)

В данном документе приведен словарь основных терминов, концепций и бизнес-сущностей проекта **Morphs Business OS (ai-saas-builder)**.

---

## 🤖 Агенты и Рой (Agents & Swarm)

* **Морф (Morph) / Морф-агент** — специализированный, узкопрофильный автономный AI-агент, выполняющий конкретную роль в цикле разработки SaaS-приложения (например, генерация API, аудит безопасности, написание тестов, автоисправление ошибок).
* **Рой (Swarm)** — децентрализованная группа взаимодействующих друг с другом морф-агентов. Координируется через асинхронную шину событий без жесткого централизованного планировщика.
* **Core Mind (Ядро разума)** — основной сервис управления роем и локального/облачного инференса LLM. Выступает шлюзом между внешними запросами и роем агентов.
* **Orchestrator (SwarmOrchestrator)** — агент-координатор, который принимает бизнес-требования пользователя, строит верхнеуровневый план действий и контролирует прохождение FSM-состояний с шага на шаг.
* **Debate Bus (Шина дебатов)** — механизм консенсуса, в котором несколько агентов (например, Агент-Кодер и Агент-Архитектор) спорят по поводу сгенерированного кода, проверяют его инварианты и голосуют за принятие или отклонение изменений.

## 🛠️ Специализированные Морфы (Specialized Morphs)

* **APIMorph** — морф, отвечающий за автоматическую кодогенерацию REST/gRPC API бэкенда на FastAPI.
* **ReactorMorph** — реактивный агент, который анализирует поступающие бизнес-события (Business Events) с помощью RAG (базы знаний бизнес-правил) и определяет необходимые изменения в базе данных или интерфейсе.
* **HealerMorph (Морф-целитель)** — агент, запускающийся в случае падения сборки или тестов воркспейса. Он анализирует трейсы ошибок и автоматически накладывает патчи (fixes) на исходный код.
* **VerificationMorph** — агент контроля качества. Запускает статический анализ, интеграционные тесты и E2E тесты на базе Playwright / Vitest для подтверждения работоспособности сгенерированного кода.
* **DeployMorph** — DevOps-агент, упаковывающий сгенерированное SaaS-приложение в изолированный Docker-контейнер и создающий манифесты для развертывания.
* **SecurityMorph** — агент безопасности, проверяющий сгенерированный код на уязвимости (SQL-инъекции, XSS, небезопасные зависимости) перед коммитом.
* **CodeLensMorph** — агент-аналитик, отвечающий за построение графа зависимостей AST кодовой базы воркспейса и наполнение графовой БД Kùzu.
* **TaskProofMorph** — агент фиксации доказательств. Создает защищенную директорию задачи и записывает туда все логи, треки, сгенерированные файлы и результаты тестирования как неопровержимые улики (proofs) успешности выполнения работы.

## 🛡️ Безопасность и Валидация (Security & Validation)

* **YOLOClassifier** — интеллектуальный перехватчик bash-команд. Анализирует запускаемые агентами shell-команды на предмет вредоносности (удаление корня, форматирование диска, утечка ключей). Использует гибрид регулярных выражений и LLM-проверки.
* **InjectionGuard** — система обнаружения атак типа "Prompt Injection" (внедрение инструкций). Сканирует `stdout` выполнения команд и внешние файлы на попытки перепрограммирования агентов (например, фразы "Ignore all previous instructions...").
* **AST Invariant (Инвариант AST)** — математически доказуемое синтаксическое правило структуры кода. Используется для формальной проверки сгенерированного React TSX или Python кода до запуска тестов.

## 💾 Данные и Память (Data & Memory)

* **Чертеж (Blueprint)** — JSON-файл спецификации SaaS-приложения, описывающий выбранные бизнес-модули (например, "booking", "loyalty"), настройки UI и текущие состояние развертывания.
* **Воркспейс (Workspace)** — изолированная папка внутри каталога `workspaces/`, представляющая собой отдельный git-репозиторий (или git worktree), в котором генерируется код конкретного B2B-приложения.
* **LanceDB (Векторный слой памяти)** — векторная СУБД, используемая для семантического поиска фрагментов кода и документации по кодовой базе (RAG-контекст).
* **Kùzu (Графовый слой памяти)** — графовая СУБД, используемая для отслеживания AST-зависимостей между компонентами системы.
