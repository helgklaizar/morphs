# Спецификация API (API Specification)

В данном документе приведена спецификация REST API-интерфейсов, предоставляемых сервисом Core Mind и встроенным дашбордом графовой базы данных Kùzu.

Сервер по умолчанию запускается на порту `8000` под управлением ASGI-сервера Granian (интерфейс `http://localhost:8000`).

---

## 1. Основные эндпоинты Core Mind API

### 1.1. Проверка работоспособности (Healthcheck)
* **Эндпоинт**: `GET /`
* **Описание**: Проверяет, запущено ли ядро Core Mind.
* **Ответ**:
  ```json
  {
    "status": "Core Mind is running"
  }
  ```

### 1.2. Стрим системного лога (Server-Sent Events)
* **Эндпоинт**: `GET /api/v1/logs`
* **Описание**: Возвращает SSE-поток системных логов в реальном времени. Используется фронтендом для вывода консоли сборки.
* **Content-Type**: `text/event-stream`

### 1.3. Стрим чат-уведомлений (Server-Sent Events)
* **Эндпоинт**: `GET /api/v1/chat_stream`
* **Описание**: Возвращает SSE-поток текстовых уведомлений от агентов роя в процессе генерации.
* **Content-Type**: `text/event-stream`

### 1.4. Получение профиля
* **Эндпоинт**: `GET /api/v1/profile`
* **Описание**: Возвращает текущий профиль B2B-приложения из SQLite.

### 1.5. Получение списка шаблонов (Blueprints)
* **Эндпоинт**: `GET /api/v1/blueprints`
* **Описание**: Сканирует файлы `../blueprints/*.json` и возвращает массив доступных шаблонов B2B SaaS.

### 1.6. Отправка бизнес-события
* **Эндпоинт**: `POST /api/v1/event`
* **Описание**: Сохраняет входящее бизнес-событие, отправляет уведомление в Telegram через `SyncDaemon` и асинхронно запускает `ReactorMorph` для адаптации UI.
* **Тело запроса**:
  ```json
  {
    "event_type": "ORDER_CREATED",
    "payload": "{\"order_id\": \"1234\", \"total\": 1500}"
  }
  ```
* **Ответ**: `{"status": "saved and analyzing"}`

### 1.7. Выполнение SQL-запросов (SQLite)
* **Эндпоинт**: `POST /api/v1/sql`
* **Описание**: Позволяет выполнять запросы напрямую к базе данных `morphs_system.db`.
* **Тело запроса**:
  ```json
  {
    "query": "SELECT * FROM tasks WHERE status = ?",
    "params": ["success"]
  }
  ```

### 1.8. Генерация UI-компонента
* **Эндпоинт**: `POST /api/v1/generate`
* **Описание**: Инициирует процесс сборки UI для выбранного типа бизнеса и набора модулей. Очищает историю логов и запускает `SwarmOrchestrator` в фоновом режиме.
* **Тело запроса**:
  ```json
  {
    "business_type": "cafe",
    "modules": ["booking", "loyalty"]
  }
  ```
* **Ответ**:
  ```json
  {
    "status": "accepted",
    "message": "Morph Forge is orchestrating."
  }
  ```

### 1.9. Чат с агентами роя
* **Эндпоинт**: `POST /api/v1/chat`
* **Описание**: Отправляет текстовую инструкцию или запрос от пользователя напрямую в оркестратор роя.
* **Тело запроса**:
  ```json
  {
    "message": "Добавь кнопку подтверждения заказа на форму бронирования",
    "business_type": "cafe"
  }
  ```
* **Ответ**: `{"status": "accepted"}`

### 1.10. Развертывание (Deploy)
* **Эндпоинт**: `POST /api/v1/deploy`
* **Описание**: Сигнализирует `DeployMorph` сгенерировать конфигурационный `Dockerfile` и развернуть контейнер проекта.
* **Ответ**: `{"status": "deployed"}` или `{"status": "failed"}`

## 2. Дашборд графа Kùzu (Kuzu Graph API)
Префикс эндпоинтов: `/api/v1/kuzu`

### 2.1. Получение графа в D3-формате
* **Эндпоинт**: `GET /api/v1/kuzu/graph`
* **Описание**: Возвращает все вершины (File, ClassNode, FuncNode) и ребра (CONTAINS_CLASS, CONTAINS_FUNC) для интерактивной визуализации связей с помощью D3.js.
* **Ответ**:
  ```json
  {
    "nodes": [
      { "id": "file::main.py", "label": "main.py", "type": "file", "group": 1 }
    ],
    "links": [
      { "source": "file::main.py", "target": "func::boot_mind", "type": "CONTAINS_FUNC" }
    ]
  }
  ```

### 2.2. Статистика графа
* **Эндпоинт**: `GET /api/v1/kuzu/stats`
* **Описание**: Возвращает количественные метрики графа AST.
* **Ответ**:
  ```json
  {
    "files": 45,
    "classes": 12,
    "functions": 182,
    "edges": 194
  }
  ```

### 2.3. Пересборка графа
* **Эндпоинт**: `POST /api/v1/kuzu/rebuild`
* **Описание**: Запускает `CodeLensMorph` для полного пересканирования AST исходного кода воркспейса и обновления графа Kùzu.
* **Параметры запроса**: `workspace` (string, опционально, путь к воркспейсу. По умолчанию — текущая директория).
* **Ответ**: `{"status": "rebuilt", "workspace": "/path/to/project"}`

### 2.4. Экспорт графа в JSON
* **Эндпоинт**: `GET /api/v1/kuzu/export/json`
* **Описание**: Полный дамп графа в плоскую структуру JSON.

### 2.5. Экспорт связей в CSV
* **Эндпоинт**: `GET /api/v1/kuzu/export/csv`
* **Описание**: Скачивание файла CSV, содержащего все дуги зависимостей AST.
* **Content-Type**: `text/csv`

### 2.6. Поиск по графу
* **Эндпоинт**: `GET /api/v1/kuzu/search`
* **Описание**: Находит ноды в графе, чьи имена совпадают с запросом.
* **Параметры запроса**: `q` (string, обязательный, длина от 1 символа).
* **Ответ**:
  ```json
  {
    "query": "healer",
    "results": [
      { "type": "class", "name": "HealerMorph", "file": "healer_morph.py" }
    ],
    "count": 1
  }
  ```
