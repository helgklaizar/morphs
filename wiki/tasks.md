# Задачи и бэклог (Tasks & Backlog)

В данном документе перечислены текущие задачи, обнаруженные технические долги и планируемые улучшения для системы Morphs Business OS.

---

## 1. Приоритетные технические задачи (Technical Debt)

### 1.1. Исправление структуры импортов и путей пакетов
* **Проблема**: В кодовой базе наблюдается путаница с путями импорта. Файлы импортируются как из корня виртуального пакета `core` (например, `from core.logger import logger`), хотя физически они лежат в папке `ml_workers`. При этом внутри `ml_workers/` существует отдельная папка `core/` для гексагональной доменной логики. Это требует создания симлинка `core -> ml_workers` и настройки `PYTHONPATH` для корректного запуска тестов и сервера.
* **Решение**: Реструктурировать папки. Либо переименовать корневую директорию `ml_workers` в `core` (объединив структуру), либо обновить все абсолютные импорты на относительные, чтобы избежать коллизий имен.

### 1.2. Стабильность Redis и обработка разрывов соединений
* **Проблема**: Текущий `EventBus` (`event_bus.py`) подключается к Redis при запуске, но не гарантирует автоматическое восстановление соединения при кратковременном падении Redis-сервера.
* **Решение**: Добавить логику повторного подключения с экспоненциальной задержкой (Exponential Backoff) в метод `connect()` шины событий.

## 2. Развитие функционала Morphs Swarm

### 2.1. Доработка MCTS в `QuantumAtropos`
* **Задача**: Расширить возможности поиска дерева Монте-Карло для симуляции сложных многоэтапных рефакторингов кода (сейчас глубина поиска ограничена простыми операциями записи).
* **Метрика успеха**: Снижение количества итераций исправления ошибок (healer loops) при генерации UI-компонентов.

### 2.2. Улучшение изоляции песочницы `BashHarness`
* **Задача**: Интегрировать легковесные контейнеры или Docker-in-Docker для запуска bash-команд, чтобы полностью предотвратить доступ Morphs к хост-системе разработчика (даже при успешном обходе `YOLOClassifier`).
* **Метрика успеха**: Полная изоляция дискового пространства и сети для запускаемых агентами команд.

### 2.3. Автоматическая очистка и оптимизация памяти в `CronMorph`
* **Задача**: Реализовать периодические задачи для сжатия базы данных графа `Kùzu` и оптимизации индексов `LanceDB` во время простоя системы.

## 4. Перспективные архитектурные задачи

### 4.1. Оптимизация локального инференса (MLX)
* **Проблема**: В текущей реализации `mlx_agent.py` локальные модели загружаются динамически, что может приводить к задержкам и просадкам по памяти на устройствах Apple Silicon при частых вызовах.
* **Решение**: Добавить пул предзагруженных моделей с ленивой инициализацией и кэшированием весов. Реализовать автоматический выбор квантования (4-bit/8-bit) в зависимости от объема свободной унифицированной памяти устройства.

### 4.2. Автоматическая локализация (i18n) сгенерированных приложений
* **Проблема**: Агенты генерируют код на английском языке, однако B2B-клиенты могут требовать интерфейс на русском или других языках в зависимости от настроек их бизнес-профиля.
* **Решение**: Интегрировать поддержку интернационализации (react-i18next на фронтенде и Babel/FastAPI i18n на бэкенде) непосредственно в шаблоны генерации `APIMorph` и `UI-Morph`.

### 4.3. Мониторинг затрат и лимитов (Economy & Cost Tracking)
* **Проблема**: Базовые лимиты описаны в `cost_limits.json`, а трекинг осуществляется через `CostHook`. Однако отсутствует API и UI для наглядного отображения затрат по конкретным задачам или агентам.
* **Решение**: Разработать эндпоинт `GET /api/v1/economy/stats` для сбора агрегированных данных о потреблении токенов и выводить финансовую аналитику в интерфейс дашборда.
